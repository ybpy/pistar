

## 3. 数据类型和字段语义

每帧应包含以下信息：

| 数据 | 含义 |
| --- | --- |
| 图像 | 主视角和腕部视角观测 |
| 状态 | 机器人当前关节和夹爪状态 |
| 动作 | 当前状态对应的实际执行动作 |
| `intervention` | `0` 表示策略自主执行，`1` 表示人工接管 |
| `value_label` | 当前状态的价值目标，用于训练 VLM 价值模型 |
| `reward` | 用于判断是否成功，成功在终帧为 `1` ，否则0|
| `reward_label` | 用于计算时序优势的逐帧奖励信号 |
| `adv_ind` | PiStar 的优势条件，通常为 `positive`、`negative` 或 `none` |

## 4. 成功、失败和接管数据

### 成功 episode

操作者确认任务完成后，该轨迹标记为成功：

- 终帧 `reward=1`，其他帧 `reward=0`；
- `value_label` 从较低价值逐步接近终点价值，终帧为 `0`；
- 非终帧 `reward_label` 表示仍需继续执行，终帧为 `0`；
- DAgger 刚采集的数据中，`adv_ind` 先保留为待处理状态，之后再由 VLM 重新判断。

### 失败 episode

操作者确认任务未完成、发生错误或需要放弃后，该轨迹标记为失败：

- 所有帧 `reward=0`；
- 所有帧的 `value_label` 使用失败惩罚值，默认是负值；
- 非终帧 `reward_label` 持续给出负向信号，终帧给出失败惩罚；
- `adv_ind` 同样等待后续 VLM 打标。

### 含人工接管的 episode

接管不单独决定 episode 成功或失败，而是描述每一帧的动作来源：

- 自主帧：`intervention=0`；
- 接管帧：`intervention=1`；
- 接管前后的自主帧仍保留，形成完整的状态分布和纠正轨迹。

如果一条轨迹全程由人工完成，它在数据语义上属于专家 demo；如果同时包含自主帧和接管帧，则属于 DAgger rollout。

## 5. 数据整理顺序

数据采集完成后，按以下顺序处理：

1. **质量检查**：剔除空轨迹、图像缺失、状态异常、时间顺序错误或机器人未正常执行的 episode。
2. **统一格式**：使 demo 和 rollout 使用相同的图像、状态、动作、任务文本和标签字段。
3. **合并数据**：把初始 demo 与新采集的 rollout 合并，形成当前训练轮次的数据集。合并只负责汇总，不负责猜测缺失标签或重新判断成败。
4. **保留来源信息**：通过 `intervention` 区分专家动作和策略动作，不能把两类数据混成同一种来源。

## 6. VLM 价值学习和优势标注

合并后的数据先用于训练 VLM 价值模型。VLM 根据图像、任务和 `value_label` 学习判断当前状态距离成功还有多远。

训练完成后，VLM 对 rollout 的状态进行价值预测，并结合 `reward_label` 计算每个自主帧的时序优势：

`优势 = 未来一段时间的奖励 + 后续状态价值 - 当前状态价值`

随后进行优势标注：

- 人工接管帧（`intervention=1`）直接视为专家纠正，标记为 `positive`；
- 自主帧按优势高低排序，优势最高的一部分标记为 `positive`，其余标记为 `negative`；
- 当前流程默认从自主 rollout 中选取优势最高的 30%；
- 初始 demo 的专家正例标签保留，不被 rollout 的重新标注覆盖。

因此，`adv_ind=none` 只是 rollout 在 VLM 处理前的临时状态，不应直接作为下一轮 PiStar 训练的最终标签。

## 7. 下一轮 PiStar 训练

完成优势标注后，使用“demo + rollout + `adv_ind`”的合并数据继续训练 PiStar。训练数据同时包含：

- 专家示范和人工接管提供的正确动作；
- 策略自主执行时访问到的真实状态；
- VLM 生成的正/负优势条件。

训练完成后得到新策略，再进行下一轮 rollout 和接管采集。每一轮都重复“自主执行 → 必要时人工接管 → 成败标注 → 数据合并 → VLM 价值学习 → 优势标注 → PiStar 继续训练”。

## 8. 训练阶段的 30% `adv_ind` dropout

训练时不会随机删除 30% 的帧、轨迹或动作。每次使用一个样本时，PiStar 以约 30% 的概率暂时不把该样本的 `adv_ind` 条件放入输入文本，以约 70% 的概率保留它。

这样做的作用是让策略既能利用优势条件，也能在没有优势条件时正常执行，降低对单一提示条件的依赖。该随机处理只发生在训练输入阶段，不改变数据集里保存的 `adv_ind`，推理阶段也不会随机丢弃用户提供的优势条件。

## 9. 闭环结果

最终形成的数据闭环是：

**专家 demo 初始化策略 → 策略自主 rollout → 困难状态人工接管 → 标注成功/失败 → 合并历史数据 → VLM 学习价值 → 生成优势标签 → PiStar 继续训练 → 新一轮 rollout。**

这个闭环的核心不是只增加成功样本，而是持续收集策略自身会遇到的状态，并用人工接管动作和价值/优势标签指导策略改进。
