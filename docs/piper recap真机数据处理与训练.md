# Piper 真机recap数据处理与训练流程

本文根据 PiStar README 中的 Piper 真机部分整理，重点说明真机数据如何采集、整理、标注，并用于后续策略训练。

## 1. 整体闭环

Piper 真机训练采用“示范初始化、策略执行、人工纠正、价值标注、继续训练”的迭代流程：

**人工示范 → 初始 PiStar 策略 → 真机自主执行 → 必要时人工接管 → 成功/失败标注 → 合并数据 → VLM 学习价值 → 生成优势标签 → PiStar 继续训练**

每一轮训练都会产生一个新的策略。新策略继续在真机上执行并收集数据，数据再进入下一轮训练。

## 2. 真机数据来源

### 2.1 人工 demo 数据

操作员通过主从遥操作完整示范任务，从臂按照主臂动作执行。由于每一帧都由人工控制，这类数据属于专家示范数据，默认视为成功的正向样本。

demo 的作用是为 PiStar 提供初始的状态分布和正确动作，通常用于训练第一版策略，也会在后续轮次中持续保留。

### 2.2 DAgger rollout 数据

初始策略训练完成后，让 PiStar 在真机上自主执行任务。执行过程中，操作员可以在策略出现错误趋势、进入困难状态或需要示范时接管机器人；纠正完成后再切回自主执行。

这类数据同时包含策略动作和专家纠正动作，能够覆盖策略实际会遇到的状态，因此是后续策略改进的主要数据来源。

### 2.3 纯推理数据

如果只需要验证策略效果而不参与训练，可以进行纯推理。这类运行不保存 DAgger rollout，不进入后续数据闭环。

## 3. 采集要求

- 主臂用于人工接管，从臂用于执行策略或跟随主臂。
- 主臂和从臂需要独立通信，保证自主控制和接管切换稳定。
- 持续记录主视角、腕部视角、机器人状态和实际执行动作。
- 所有 episode 使用一致的任务文本、相机视角、状态定义和动作定义。
- 每个 episode 从统一初始位姿开始，结束后复位，避免不同初始状态造成数据分布混乱。
- 采集结束时必须明确记录任务成功或失败；无法判断结果的轨迹不应直接用于训练。

## 4. 一个 episode 的数据流

1. 机器人复位到初始状态，开始记录图像、状态和动作。
2. 策略自主执行时，记录策略访问到的状态和策略实际执行的动作。
3. 发生人工接管时，继续记录数据，并把接管期间的帧标记为人工控制。
4. 接管结束后恢复自主执行，后续帧重新标记为策略控制。
5. episode 结束后，根据任务结果给整条轨迹写入成功或失败相关标签。
6. 保存完整轨迹，保留自主帧和接管帧的时间顺序，不只保存最后的接管片段。

一条 DAgger 轨迹可以是全程自主，也可以是“自主 → 接管 → 自主”。人工接管是逐帧属性，成功或失败是 episode 级别属性，两者不能混淆。

## 5. 数据字段及其用途

| 字段 | 用途 |
| --- | --- |
| `image`、`wrist_image` | 提供主视角和腕部视角观测 |
| `state` | 记录当前机器人状态，作为策略输入 |
| `actions` | 记录对应的动作监督目标 |
| `intervention` | 区分动作来源：`0` 为策略自主，`1` 为人工接管或 demo |
| `value_label` | VLM 价值模型的监督目标 |
| `reward` | 表示任务最终是否成功的稀疏奖励 |
| `reward_label` | 为后续时序优势计算提供逐帧奖励信号 |
| `adv_ind` | PiStar 使用的优势条件，最终通常为 `positive` 或 `negative` |

除训练字段外，还应保留 episode、帧序号和时间等元数据，以便按轨迹检查和处理。

## 6. 成功与失败轨迹的标签

### 6.1 成功轨迹

任务完成后，轨迹作为成功数据处理：

- `reward` 通常只有最后一帧为 `1`，其余帧为 `0`；
- `value_label` 随着轨迹接近成功逐渐升高，终帧为成功价值；
- `reward_label` 的终帧为 `0`，非终帧提供继续执行的信号；
- rollout 刚采集时的 `adv_ind` 只是临时占位，后续由 VLM 重新标注。

### 6.2 失败轨迹

任务未完成、发生错误或被放弃后，轨迹作为失败数据处理：

- `reward` 全部为 `0`；
- `value_label` 使用统一的失败惩罚值；
- `reward_label` 在终帧给出失败惩罚，非终帧保持负向的继续执行信号；
- `adv_ind` 等待 VLM 根据状态价值和优势重新判断。

失败数据不能简单删除。它们帮助价值模型识别危险状态，也让策略学习哪些状态和动作应该避免。

## 7. 数据检查与合并

采集完成后，先进行数据质量检查：

- 删除空 episode、图像缺失、状态异常或时间顺序错误的数据；
- 检查任务文本、图像尺寸、状态维度和动作维度是否一致；
- 检查成功/失败结果是否明确；
- 检查 `intervention` 是否真实反映每个时间段的控制来源。

检查通过后，将人工 demo 和 DAgger rollout 合并为当前轮次的数据集。合并的作用是汇总数据，不负责补齐缺失标签、不重新判断成功失败，也不替代数据质量检查。

后续轮次可以继续加入新的 rollout，并保留历史 demo 和历史 rollout，形成更完整的数据分布。

## 8. VLM 价值学习与优势标注

合并数据首先用于训练 VLM 价值模型。模型根据图像、任务文本和 `value_label` 学习估计当前状态距离任务成功的程度。

训练完成后，VLM 对 rollout 状态进行预测，并结合 `reward_label` 计算时序优势。优势反映某个动作或状态相对于当前策略预期的好坏：

**优势 = 未来一段时间的奖励 + 后续状态价值 − 当前状态价值**

根据优势生成 `adv_ind`：

- 人工接管帧属于专家纠正，标记为 `positive`；
- 自主 rollout 帧按优势排序，优势较高的一部分标记为 `positive`，其余标记为 `negative`；
- 默认从自主 rollout 中选取优势最高的 30% 作为正向样本；
- 原始 demo 的专家正向标签保留，不因 rollout 的重新标注而改变。

因此，rollout 中的 `adv_ind=none` 只表示“尚未完成优势标注”，不能直接作为下一轮训练的最终状态。

## 9. PiStar 继续训练

完成 VLM 优势标注后，使用已经合并且完成 `adv_ind` 标注的数据继续训练 PiStar。下一轮训练同时利用：

- demo 和人工接管提供的专家动作；
- 策略自主执行时访问到的真实状态；
- 成功/失败轨迹提供的价值和奖励信息；
- VLM 生成的正向和负向优势条件。

训练得到的新策略再次部署到 Piper 真机，继续执行、接管和采集。这样逐轮减少策略在困难状态下对人工接管的依赖。

## 10. `adv_ind` 的训练使用方式

训练时，`adv_ind` 作为策略输入条件使用。为避免策略完全依赖该条件，训练过程会以约 30% 的概率暂时不使用样本中的 `adv_ind`，其余约 70% 的概率正常使用。

这个随机处理只作用于训练输入，不会删除数据帧、episode 或动作，也不会修改数据集保存的标签。推理时则按照指定的优势条件使用，不进行随机丢弃。

## 11. 最终数据闭环

Piper 真机训练的核心流程可以概括为：

1. 用人工 demo 学习基本任务动作；
2. 让策略自主执行，收集策略访问到的真实状态；
3. 在困难状态进行人工接管，记录专家纠正；
4. 对每条轨迹标记成功或失败；
5. 合并历史数据和新 rollout；
6. 用 VLM 学习价值并生成优势标签；
7. 用带优势标签的数据继续训练 PiStar；
8. 部署新策略，开始下一轮采集。

这个过程持续把“策略会遇到的问题”加入训练数据，使策略从单纯模仿示范逐步转向能够处理自身分布状态的闭环学习。
